# 공개 사본 검토·마스킹 (무인 실행)

이 세션은 dotclaude 동기화가 띄운 무인 실행이다. 사용자에게 질문할 수 없다.
**수정은 작업 폴더의 `stage/` 아래 사본에만 한다.** 원본 레포는 절대 고치지 않는다.

## 배경

사용자는 Claude Code 사용 환경(스킬, 훅, 설정, 프로젝트별 Claude 설정, 아카이브)을 비공개 레포에 두고,
그 공개 사본을 자동으로 만들어 다른 사람과 경험을 공유한다. 이 세션은 내용이 바뀐 항목만 받아 공개해도 되는지 판단하고,
필요하면 식별 정보를 가린다. 여기서 공개로 판정한 내용은 사람 확인 없이 공개 GitHub 레포에 올라간다.

## 항목별 판정

각 항목의 `stage/<항목 경로>` 아래 파일을 전부 읽고 셋 중 하나로 판정한다.

- `public`: 가릴 것이 없다. 사본을 고치지 않는다
- `masked`: 식별 정보를 자리표시자로 바꾸면 공개할 가치가 남는다. 사본을 고친다
- `private`: 내용 대부분이 사용자 개인 정보(성격, 경력, 목표, 구직 활동, 개인 메모 등)이거나, 가리고 나면 뼈대만 남아 의미가 없다. 사본을 고치지 않는다

원칙: **공개에 필요 없는 식별 정보는 모두 가린다.** 워크플로우를 이해하는 데 필요 없는 구체값이면 가린다고 보면 된다.

가릴 것 (masked 일 때 자리표시자로 바꾼다)
- 사용자 로컬의 위치 (홈 아래 Desktop·Documents 같은 개인 폴더로 시작하는 경로, 레포를 모아 두는 폴더 이름).
  경로를 통째로 가리지 말고 **상대경로로 바꿔 구조는 남긴다**
  - 프로젝트 안의 경로 → 프로젝트 루트 기준 (`.claude/hooks/check.sh`, `backend/src/`). 훅 명령·스크립트 안이면 `$CLAUDE_PROJECT_DIR/...`
  - 다른 레포를 가리키는 경로 → 레포들을 모아 둔 작업 폴더 기준 (`../<SERVER_REPO>`, `../<APP_REPO>/lib/`)
  - `~/.claude/...` 처럼 Claude Code 설정 위치는 누구에게나 같으므로 그대로 둔다
- 회사·조직·학교·교육 프로그램·제품·서비스 이름 → `<COMPANY>`, `<PRODUCT>`, `<SERVICE>` 등 역할이 드러나는 이름.
  레포 이름은 `<SERVER_REPO>`, `<APP_REPO>` 처럼 역할로
- 클라우드 프로젝트 ID, 버킷, 인스턴스, 도메인, 내부 URL, Slack 채널·워크스페이스 ID → `<GCP_PROJECT_ID>`, `<BUCKET>`, `<SLACK_CHANNEL_ID>` 등
- 토큰·키·비밀번호 → `<SECRET>`
- 사람 이름, 이메일, 전화번호, 계정명 (GitHub 조직·사용자명 포함) → `<PERSON>`, `<EMAIL>`, `<GITHUB_ORG>` 등
- 사용자 홈 경로(`/Users/<이름>/...`)와 개인 이름이 들어간 폴더명 → 위와 같이 상대경로로
- 사용자의 경력·학업·구직 사실: 재직·퇴사 이력, 이전 직장의 사업 분야(예: "AI ○○ 서비스"), 학생 신분, 수업·과제 이름,
  지원한 회사, 자기소개서 내용. 필요하면 "이전 직장", "개인 프로젝트" 정도로만 쓴다
- 고유 식별자: 인스턴스·MIG·Cloud Function·내부 스크립트 이름, 리전, 내부 API 경로, 이슈 트래커 ID(예: `PROJ-12`),
  세션 ID·UUID, 실제 소스 파일 이름. 구조 설명에 필요하면 `<INSTANCE>`, `<ISSUE_ID>`, `<API_PATH>`, `example.dart` 처럼 바꾼다
- 파일명·디렉토리명에 위 이름이 들어 있으면 일반화한다. 새 이름으로 파일을 쓰고, 원래 파일은 결과의 `delete` 에 적는다
  (이 세션에는 삭제 도구가 없다. 스크립트가 지운다). 참조도 같이 고친다
- 차단 목록 파일의 문자열은 하나도 남으면 안 된다 (대소문자 무시, 부분 일치)

가리지 않아도 되는 것: 공개 기술·도구 이름(LiveKit, Sentry, FastAPI, GCP 서비스명 등), 일반적인 워크플로우 설명, Anthropic 관련 표기

## 항목 사이 일관성

항목끼리 파일을 참조할 수 있다 (예: 스킬이 `archive/skills/_shared/personas/...` 를 참조). 파일 이름이나 자리표시자를 바꿀 때는
같은 배치의 다른 항목과, 이미 공개된 사본(공개 레포 경로는 아래에 준다)의 이름을 Grep 으로 확인해 똑같이 맞춘다.

## 이름

항목 경로의 마지막 이름(예: `skills/<이름>`, `projects/<이름>`)에 가릴 것이 있으면 `public_name` 에 일반화한 이름을 준다
(영문·숫자·하이픈). 가릴 것이 없으면 생략한다.

## 결과

```json
{
  "items": [
    {"item": "archive/skills/foo", "verdict": "masked",
     "public_name": "생략 가능",
     "delete": ["stage/archive/skills/foo/이름을-바꾼-원래-파일.md"],
     "summary": "공개 목록(EXPORT.md)에 들어갈 한 문장 설명 (무엇을 하는 것인지, 한국어)",
     "blinded": "무엇을 가렸는지 한 줄 (예: 회사명, GCP 프로젝트 ID)",
     "reason": "판단 사유 한 문장"},
    {"item": "memory/bar", "verdict": "private", "reason": "개인 선호 메모라 가리면 의미가 없음"}
  ]
}
```
summary·blinded·public_name·reason 에도 가려야 할 이름을 쓰지 않는다. 항목을 빠뜨리지 않는다.
