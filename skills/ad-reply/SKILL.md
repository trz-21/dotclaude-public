# <SERVICE> 광고 메일 답장 초안

<AD_EMAIL> 은 `mcp__claude_ai_Gmail__*` 커넥터 계정이다 (`mcp__gmail-<ADMIN>__*` 는 관리자 계정이라 쓰지 않는다).
기준 문서는 노션 `<NOTION_PAGE_PATH>` 의 「1. 자동화 설계서」「2. 메일 유형별 처리 규칙」이다. 이 스킬과 노션이 다르면 노션 최신 내용을 따르고, 차이를 사용자에게 알린다.

## 1. 절대 규칙

- 메일을 **보내지 않는다**. `create_draft` 로 초안만 만든다. 발송은 사람이 한다.
- 읽음 상태와 라벨은 바꾸지 않는다 (동료 Windows 자동화 `/ad-mail` 과 같은 메일함을 공유한다).
- 확정되지 않은 가격·일정·조건을 약속하지 않는다. 모르면 초안에 `[확인 필요: …]` 로 남기고 사용자에게 알린다.

## 2. 답장할 메일 고르기

1. `search_threads` 로 `to:<AD_EMAIL> newer_than:7d` 를 찾는다 (사용자가 기간을 말하면 그 기간).
2. 스레드마다 `get_thread`(PLAIN_TEXT)로 **마지막 메시지의 발신자**를 본다. 결과가 크면 파일로 저장되니 jq 로 `date, sender, labelIds, 첨부 파일명`과 인용을 뺀 본문만 뽑는다.
   - 마지막이 <AD_EMAIL> → 이미 답장함, 건너뜀
   - 마지막이 상대의 감사 인사·확인 완료 → 답장 불필요, 건너뜀
   - noreply(Google Ad Manager, Search Console, AdSense 등) → 건너뜀
3. `list_drafts` 로 같은 threadId 의 초안이 이미 있는지 확인한다. 있으면 새로 만들지 않고 알린다 (자동화 중복 방지).
4. 답장 대상 목록과 건너뛴 이유를 먼저 짧게 정리한 뒤 초안을 만든다.

## 3. 초안 형식

- `create_draft` 에 `replyToMessageId`(상대 마지막 메시지 id), `to`(상대), `subject`("Re: " + 원제목) 를 넣는다. 원 메일의 참조(cc)는 그대로 유지한다 (대행사는 참조 3~4명).
- `includeSignature` 는 서명을 붙여주지 않는다. 아래 서명을 `htmlBody` 에 직접 넣고, `body` 에도 텍스트 서명을 넣는다.
- 첫 줄: `안녕하세요, {이름} 담당자님.` (이름을 모르면 `안녕하세요, 담당자님.`) 다음 줄 `<SERVICE> 광고팀 <PERSON>입니다.`
- 끝: `감사합니다.` / `<PERSON> 드림` 뒤에 서명.
- 짧은 처리 완료 회신(소재 교체 완료 등)은 2~4줄로 끝낸다. 상품 안내는 번호 매긴 소제목(1. 2. 3.)으로 정리한다.
- 본문은 정중한 "~드립니다/~부탁드립니다" 체. 과장·이모지 없이.

서명 (텍스트):
```
------------------------------
<SERVICE> 광고팀 드림
MAIL. <AD_EMAIL>
PHONE. <PHONE> (담당자: <PERSON>)
```

서명 (HTML, 기존 발송 메일과 동일):
```html
<br><hr style="color:rgb(51,51,51)"><div><span style="color:rgb(0,0,0);font-size:12px;line-height:18px"><b><font face="arial, sans-serif"><SERVICE> 광고팀 드림</font></b></span></div><div><span style="color:rgb(0,0,0);font-size:12px;line-height:18px"><font face="arial, sans-serif"><b>MAIL.</b> <a href="mailto:<AD_EMAIL>"><AD_EMAIL></a></font></span></div><div><span style="color:rgb(0,0,0);font-size:12px;line-height:18px"><b>PHONE</b>. <PHONE> (담당자: <PERSON>)</span></div>
```

## 4. 상품과 정책 (안내할 때 쓰는 값)

**배너 광고** (1주 단위, 최소 1주, VAT 별도, PNG·JPG·GIF)

| 구좌 | 1주 | 규격 |
| --- | --- | --- |
| PC 메인 B | <PRICE> | 728×90 |
| PC 게시판/게시물 | <PRICE> | 300×250 (2·3열은 300×100) |
| 모바일 메인 | <PRICE> | 320×50 (+정사각 CI 1개, 노출 문구 1개) |
| 모바일 메인 서브 | <PRICE> | 300×250 |
| 모바일 게시판/게시물 | <PRICE> | 320×50 |
| SNS 광고 | 1회 <PRICE> (배너 병행 시 <PRICE>) | 카드뉴스 10장, 1:1 |

- PC 메인 A 는 먼저 권하지 않는다(규격 미확정). 광고주가 지정하면 사용자 확인으로 넘긴다.
- 상세는 광고안내서 첨부로 안내한다. 파일: `<AD_GUIDE_PDF_PATH>` (첨부 이름은 `<AD_GUIDE>.pdf`). 첨부가 필요하면 base64 로 넣는다.
- 소재와 랜딩 URL 은 게재 2일 전까지 받는다.

**유료 제휴** (1개월 이상)
- 배너 노출 + 제휴게시판 [공식제휴] 게시물, 게시물 제목이 PC 메인 좌측 하단·모바일 메인 하단·각 게시판 목록 상단 바에 노출
- 광고주 전용 <SERVICE> 계정 발급(댓글 소통), 제휴 기간 동종 업종 중복 제휴 없음
- 비용은 함께 쓰는 배너 구좌에 따라: 모바일 메인 월 <PRICE>, 모바일 게시판/게시물 월 <PRICE> (VAT 별도)

**무료 제휴**
- <SERVICE> 회원·<SCHOOL> 구성원**에게만** 주는 직접 혜택(무료 이용권, 전용 할인, 사은품 등)이 있을 때만 가능
- 누구나 받는 가격·무료 콘텐츠는 혜택으로 보지 않는다 → 회원 전용 혜택을 제안하거나 유료/배너 안내
- 제휴게시판 '진행중인 이벤트'에 [제휴] 말머리, 최장 3개월. 광고주 계정 없음 → 문안·이미지를 받아 운영진이 대신 게시
- 외부 기관의 모집 공고를 대신 게시하는 것은 하지 않는다

**받을 수 없는 경우**
- 유료 제휴 중인 업종과 같은 업종 → 제휴 불가, 일회성 배너만 가능하다고 안내
- 한 구좌 같은 기간 광고 7개 이상

**게시 전 검토 기준** (안내 시 함께 적는다)
- 게시글·배너 소재·랜딩 URL 은 게재 전 검토
- <SCHOOL> 명칭으로 학교 추천·공인처럼 보이는 표현, 결과(취업·성적 등)를 보장하는 표현은 수정 요청
- 조건이 있는 상품(휴대폰 등)은 적용 조건·기간·대상을 게시글에 명시하도록 요청
- 회원 불편 신고가 반복되면 게시 조정 가능

**진행 절차** (처음 문의에 안내)
희망 방식 회신 → (유료·배너) 구좌·기간 확정, 견적서 → 게시 문안·이미지·랜딩 URL 전달 → 검토 후 게시 → (유료) 세금계산서 발행.
사업자등록증 사본은 다음 경우에 받는다.
- 유료 건(유료 제휴·배너): 세금계산서 발행용
- 무료 제휴라도 오프라인 매장·대면 서비스(휴대폰 판매점, 병원, 학원 등): 사기 방지용. 문구 예: "사업자등록증 사본 (회원 보호를 위해 오프라인 매장 제휴 시 확인하고 있습니다)"
- 온라인 서비스의 무료 제휴에는 요청하지 않는다.
업종 인허가 서류(예: 판매점 사전승낙서)는 기본으로 요청하지 않는다.

## 5. 유형별 답장

| 유형 | 답장 내용 |
| --- | --- |
| 처음 광고 문의 | 감사 → 가능 여부 → 배너/유료 제휴/무료 제휴 중 맞는 것 안내 → 검토 기준 → 절차. 광고안내서 첨부 |
| 제휴 제안 | 위 정책으로 유료·무료 가능 여부 판단해 안내. 애매하면 권고안만 쓰고 사용자에게 결정을 넘긴다 |
| 무료 제휴 혜택 회신 | 회원 전용 혜택인지 확인 → 가능하면 게시 기간·문안 참고사항·전달 자료(문안·이미지·썸네일·랜딩 URL, 오프라인 업체면 사업자등록증 사본) 요청 |
| 대행사 부킹 요청 (<AGENCY> 등) | 부킹 완료 회신 + 구좌·규격·소재 마감(게재 2일 전). <AGENCY> 메인 패키지 기본값은 PC 메인 B + 모바일 메인. 랜딩 URL, 규격 오류, 구좌 미확정, 분할 일정 시각, 소재 링크 권한 다섯 가지를 점검해 빠진 것은 한 번에 요청 |
| 견적 요청 | 단가표로 금액 계산. 견적서 파일 작성은 사용자 확인 후 |
| 소재 전달·교체 | 규격 확인 → 반영 완료 회신(실제 반영은 사람이 하므로 "반영 후 완료 회신" 문장으로 쓰고 사용자에게 알림) |
| 게재 캡처 요청 | 캡처는 사람이 해야 하므로 초안만 쓰고 첨부 자리를 표시 |
| 정산·세금계산서 | 금액·작성일자 확인 문장. 발행은 사람이 홈택스에서 |
| 매체 수익화·애드네트워크 영업 (RTB, 리워드 광고 등) | 판단을 사용자에게 넘긴다. 초안은 "소개서 잘 받았고 내부 검토 후 필요 시 연락" 정도로만 쓴다 |
| 감사 인사·완료 확인, noreply | 답장하지 않는다 |

## 6. 끝나면

- 만든 초안마다: 상대, 한 줄 요지, `[확인 필요]` 항목, Gmail 링크(viewUrl)를 보고한다.
- 건너뛴 메일과 이유도 한 줄씩 적는다.
- 사용자가 방식을 고쳐주면 이 파일에 반영한다.
